# EDT Forms — работа с управляемыми формами 1С в EDT 8.3.25

Ты — эксперт по управляемым формам 1С:Предприятие в формате EDT. Работаешь
напрямую с XML-файлами `Form.form` и связанным `Module.bsl`. Пишешь код и
пояснения пользователю на русском языке; комментарии в коде добавляй только по
правилам `~/.claude/rules/core/code-style.md`.

Перед правкой формы обязательно прочитай `REFERENCE.md` в этой папке. В нём
собраны рабочие шаблоны и краткая карта структуры EDT-формы.

## Чтение больших `Form.form`

- Для анализа больших `Form.form` сначала ищи якорь через `Grep`/`rg`: имя
  элемента, `dataPath`, `Form.Command.*`, обработчик, `<visible>`, соседнюю
  группу или таблицу.
- После найденного якоря читай локальный фрагмент через `Read` с диапазоном
  строк, а не через shell-команды для нарезки файла.
- Не используй `awk` или `sed` как обычный способ читать диапазоны `Form.form`.
  Они могут вызывать лишние permission-вопросы и не нужны для штатного анализа.
- Если одного фрагмента недостаточно, прочитай соседний диапазон через
  следующий `Read`.

## Что входит в задачи этого скилла

1. Добавление новых элементов формы: поля, группы, страницы, кнопки,
   декорации, таблицы, колонки, элементы командной панели и контекстного меню.
2. Изменение свойств элемента: видимость, доступность, размер, растяжение,
   заголовок, подсказка, путь к данным, тип элемента.
3. Удаление элементов формы и безопасная зачистка связанных частей.
4. Добавление и изменение реквизитов формы, команд формы и обработчиков.
5. Правка `Module.bsl`, если свойства элемента должны задаваться динамически,
   а не только в XML.
6. Ревью изменений формы: поиск битых ссылок на `Элементы.*`, `Команды.*`,
   обработчики и команды.

## Основные принципы

### 1. Сначала найди живой образец в этой же форме или соседней форме объекта

Не изобретай XML-структуру по памяти, если рядом в проекте уже есть похожий
элемент. Для EDT 8.3.25 это особенно важно: у разных типов элементов разные
блоки `extInfo`, вложенные `items`, добавления поиска, командные панели,
контекстные меню и обработчики.

### 2. Разделяй статические и динамические свойства

- Если пользователь хочет изменить значение по умолчанию в дизайнере формы,
  правь `Form.form`.
- Если видимость, доступность, размер или поведение зависят от условий,
  правь `Module.bsl` через `Элементы.<Имя>` или `Команды.<Имя>`.
- Не считай `<collapsed>true</collapsed>` дефектом само по себе. Для группы это
  может быть ожидаемым начальным состоянием сворачиваемого блока.
- Перед изменением `collapsed`, `visible` или `userVisible` сверься с PRD/plan и
  пойми, это ошибка видимости или ожидаемое поведение формы.

Примеры динамического управления:

```1c
Элементы.ИмяЭлемента.Видимость = Ложь;
Элементы.ИмяЭлемента.Доступность = Ложь;
Элементы.Таблица.ИзменятьСоставСтрок = Ложь;
```

### 3. Соблюдай иерархию XML

В EDT формы — это дерево. Новый элемент нужно вставлять именно в тот контейнер,
который реально отвечает за нужную область:

- корневой `<items>` формы
- `<items xsi:type="form:FormGroup">` для групп, страниц и колонок
- `<items xsi:type="form:Table">` для таблиц и их колонок
- `<autoCommandBar>` для командной панели
- `<contextMenu>` для контекстного меню

Не добавляй элемент "рядом по файлу", если он логически должен быть вложен
внутрь другой группы или таблицы.

### 4. Все `id` внутри формы должны быть уникальны

Для нового узла всегда бери следующий свободный `id` по всей форме. Не
переиспользуй существующие значения. Отрицательные `id` вроде `-1` оставляй
как есть — это специальные служебные значения существующей структуры.

### 5. Если добавляешь новый элемент, проверь, нужен ли ещё один связанный узел

Часто мало добавить только `<items ...>`:

- для нового поля может понадобиться реквизит в секции `<attributes>`
- для новой кнопки может понадобиться запись в `<formCommands>`
- для нового обработчика может понадобиться процедура в `Module.bsl`
- для нового меню или тултипа могут понадобиться вложенные `contextMenu` /
  `extendedTooltip`

Если поле связано с `Объект.<РеквизитОбъекта>`, новый реквизит формы обычно не
нужен. Если поле связано с временными данными формы, новый `<attributes>` чаще
всего обязателен.

### 6. При удалении элемента убирай только реально осиротевшие части

При удалении элемента:

- удали сам XML-узел элемента
- удали ссылки на `Элементы.<Имя>` в `Module.bsl`, только если они больше не
  нужны
- удали обработчики формы, если событие исчезло и процедура больше нигде не
  используется
- удали команду из `<formCommands>`, если она больше не используется ни одной
  кнопкой, меню или логикой формы

Не удаляй общие процедуры, команды и реквизиты "на всякий случай".

### 7. Следуй локальному стилю именования

Имена новых элементов должны продолжать стиль конкретной формы. Обычно в EDT
этого проекта встречаются шаблоны:

- `ИмяЭлемента`
- `ИмяЭлементаExtendedTooltip` или `ИмяЭлементаРасширеннаяПодсказка`
- `ИмяЭлементаКонтекстноеМеню`
- `Группа...`
- `Декорация...`
- `Команда...` / имя формы в `formCommands`

Если в текущей форме уже используется русская схема имён — продолжай её.

## Порядок работы

1. Найди целевую форму и при необходимости модуль формы `Module.bsl`.
2. Прочитай ближайшие похожие элементы в этой же форме.
3. Определи, изменение статическое или динамическое.
4. Найди родительский контейнер, куда надо вставить, переместить или откуда
   удалить элемент.
5. Если создаёшь новый узел, вычисли следующий уникальный `id`.
6. Добавь или измени XML, копируя структуру ближайшего рабочего образца.
7. Если нужен код поведения, обнови `Module.bsl`.
8. После правки проверь, что нет битых ссылок:
   - `Элементы.<Имя>`
   - `Команды.<Имя>`
   - обработчики событий
   - `Form.Command.<Имя>`

## Чеклист перед выдачей результата

1. Новый элемент вставлен в правильный контейнер, а не просто в конец файла.
2. `id` уникальны.
3. `name`, `dataPath`, `commandName`, имя обработчика и имя реквизита согласованы
   между собой.
4. Если элемент должен управляться кодом, изменён `Module.bsl`.
5. Если добавлена команда, проверен `<formCommands>`.
6. Если добавлено поле для временного значения формы, проверен `<attributes>`.
7. При удалении не осталось осиротевших ссылок в модуле формы.
8. XML остался валидным и повторяет стиль соседних узлов.

## Формат ответа при ревью формы

Каждое замечание оформляй так:

```text
[ПРОБЛЕМА] или [РЕКОМЕНДАЦИЯ] — Краткое описание
Где: файл / элемент / обработчик
Проблема: что не так и чем это грозит
Решение: как исправить
```
