# Git workflow

Гигиена коммитов задана корпоративным стандартом
[`git-commits.md`](../../../doc/ai/standards/git-commits.md): один commit — один
связный набор изменений, только явное добавление в индекс, сохранность
несвязанных изменений пользователя, список того, что не коммитится никогда,
требования к сообщению, запрет push и переписывания проверенной истории.

Здесь только AIDD-дельта: чем в этом процессе является «связный набор
изменений» и кто его коммитит.

## Change-блок как единица commit

- Если tasklist использует явные блоки, именно блок является базовой единицей
  commit, а не отдельная задача внутри блока.
- Legacy-формат tasklist без блоков допустим только как режим совместимости.
- Verification-only шаги закрываются без отдельного commit.

## Роли

- Исполнитель реализует изменения внутри change-блока и не коммитит.
- Основная сессия выполняет итоговый commit change-блока и сразу после него
  обновляет связанные артефакты процесса.
- Review и fix-циклы не смешиваются с обычными implementation-коммитами без
  явного правила workflow.

## Формат

Формат тикета, ветки и commit message — project-specific, см.
`.claude/rules/project/ticketing.md`. Он имеет приоритет над общими
формулировками стандарта.
