# Git workflow

Этот файл описывает общую, переносимую политику работы с git в AIDD.

## Общие принципы

- Изменения должны группироваться в осмысленные change-блоки.
- Один change-блок соответствует одному commit.
- Commit должен отражать фактический набор изменений, а не случайное состояние
  рабочей директории.
- Форматы тикетов, веток и commit message определяются project rules.

## Change-блоки и tasklist

- Если tasklist использует явные блоки, именно блок является базовой единицей
  commit.
- Если tasklist ещё в legacy-формате без блоков, это допустимо только как
  режим совместимости.
- Verification-only шаги могут закрываться без отдельного commit, если это
  допускает workflow проекта.

## Роли и ответственность

- Исполнитель реализует изменения внутри change-блока.
- Основная сессия выполняет итоговый commit change-блока и, если требуется,
  обновляет связанные артефакты процесса.
- Review и fix-циклы не должны автоматически смешиваться с обычными
  implementation commit'ами без явного правила workflow.

## Требования к commit

- Commit должен быть неинтерактивным и воспроизводимым.
- Перед commit нужно проверить diff и убедиться, что в него попали только
  изменения текущего блока.
- Если проект задаёт специальный способ формирования commit message или staging,
  он имеет приоритет над этим документом.

## Что не делать

- Не смешивать несколько независимых change-блоков в одном commit.
- Не делать commit “заодно” для несвязанных правок.
- Не полагаться на локальные машинные настройки как на часть общего workflow.
