# Общие правила 1С / EDT / БСП

Инженерные правила 1С заданы корпоративными стандартами и здесь не повторяются:

- [`onec-bsl.md`](../../../doc/ai/standards/onec-bsl.md) — тип конфигурации и
  допустимая правка типового кода, граница клиент/сервер, структура модуля,
  стандартные атрибуты и права на перечисления, целостность данных и
  транзакции, чтение реквизитов ссылочных объектов, события записи и связанные
  объекты, проверки уникальности и конкурентная запись, привилегированный режим,
  GUID/UUID, обработчики обновления, интеграции и обмены, границы
  ответственности процедур, терминология метаданных в общении с человеком;
- [`onec-queries.md`](../../../doc/ai/standards/onec-queries.md) — запросы,
  включая запрет обращений к базе данных в циклах;
- [`agent-tools.md`](../../../doc/ai/standards/agent-tools.md) — выбор
  инструмента для discovery по 1С-коду и безопасное редактирование через
  инструментарий EDT;
- [`testing-yaxunit.md`](../../../doc/ai/standards/testing-yaxunit.md) и skill
  `mpl-yaxunit` — тесты;
- skill `mpl-1c-bsp` — работа со стандартными подсистемами БСП;
- skill `mpl-metadata-removal-impact` — удаление элементов метаданных.

Здесь только то, чего в стандартах нет: проектные помощники, локальные
соглашения именования и приоритет более узких правил.

## Приоритет правил

- Если для типа артефакта есть специализированное правило (path rule, project
  rule, skill), оно имеет приоритет над общими историческими паттернами
  репозитория.
- Рефакторинг «заодно» вне рамок тикета не делается: он оформляется отдельной
  задачей.

## GUID/UUID: проектный помощник

Стандарт запрещает подставлять GUID вручную там, где идентификаторами управляет
EDT, и допускает ручную правку XML только как задокументированный fallback. Если
при таком fallback действительно нужен новый GUID, генерируй его только через
`.claude/scripts/new-guid.cmd`.

Не генерируй GUID inline-командами вроде `powershell -Command
"[guid]::NewGuid()"`, `python -c` или `uuidgen`, и не копируй GUID из соседнего
XML-узла или похожего объекта.

Числовые `<id>` внутри `Form.form` не являются GUID: при documented gap
используй следующий свободный `id` по всей форме и не переиспользуй
существующие значения.

## Именование обработчиков обновления ИБ

Стандарт задаёт размещение обработчика и требование теста. Локальное соглашение
дополняет его именами:

- регистрирующий общий модуль проекта называется
  `ОбновлениеИнформационнойБазы<ИмяСистемы>`;
- имя метода обработчика заканчивается на
  `ПриПереходеНаВерсию_<Номер_Версии>`, например
  `ЗаполнитьДатуНачалаДействияПриПереходеНаВерсию_1_0_6_5`;
- если модуль менеджера обновляемого объекта надёжно определить нельзя,
  размещай обработчик в этом общем модуле.

## Где искать проектные ограничения

Профиль проекта, зоны изменений, именование, тикеты, тесты и известные ловушки —
в `.claude/rules/project/*.md`; ограничения по путям — в
`.claude/rules/paths/*.md`. Они уточняют стандарт, но не отключают корпоративный
skill `mpl-*` и правило безопасности.
