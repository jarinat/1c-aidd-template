# AIDD Research

Используй subagent `researcher`.

Этот skill описывает полноценный AIDD research после подготовки PRD.
Предварительное техническое исследование на этапе `idea` выполняется через
`researcher` как technical reconnaissance summary и не заменяет этот skill.

Для задач удаления элементов метаданных дополнительно используй
`.claude/skills/1c-metadata-removal-impact/SKILL.md`.

Если доступен MCP `1c-rsv`, дополнительно используй
`.claude/skills/1c-rsv-tools/SKILL.md` как discovery слой для больших
1С/EDT-кодовых баз. Он помогает искать объекты, методы, ссылки, формы,
подписки, движения, интеграции и локальные аналоги, но не заменяет чтение
исходников и AIDD-артефактов.

## Алгоритм

1. Определи ticket id: используй переданный аргумент или `aidd/docs/.active_ticket`.
2. Прочитай PRD из `aidd/docs/prd/<ticket>.prd.md`.
3. Исследуй кодовую базу:
   - если подключен `1c-rsv`, начни с MCP discovery: определи `projectName`,
     выполни релевантные discovery-операции и зафиксируй ограничения;
   - найди точки встраивания;
   - найди локальные аналоги реализации в том же модуле, объекте, форме, общем
     модуле или подсистеме;
   - для каждого значимого аналога отдели факты из кода от reference pattern:
     что реально делает код, какой инженерный подход можно наследовать, а какие
     поля, фильтры, настройки формы, права, транспортные параметры, форматы
     данных, тестовые сценарии или другие элементы scope требуют отдельного
     источника требований;
   - не выводи новый scope из аналога: если элемент есть только в похожей
     реализации, но не подтвержден PRD, входным артефактом, существующим
     AIDD-решением или явным решением пользователя, фиксируй его как
     рекомендацию, `ASSUMPTION`, `WARNING` или `Open question`, а не как
     требование;
   - проследи зависимости;
   - определи целевую зону изменений по project rules и path rules;
   - проверь, нет ли расхождений между PRD и фактическим кодом.
4. Если PRD включает переименование mdo-объекта или элемента метаданных:
   - найди прямые ссылки на старое mdo-имя в каталогах исходников проекта, тестах,
     ролях, подсистемах, `Configuration.mdo`, формах, DCS/СКД-шаблонах отчетов
     и других связанных метаданных;
   - классифицируй каждую найденную точку: `scope: update`, `scope: no-op`
     с причиной, `open question/blocker`, `explicitly out-of-scope` с
     проверяемым источником;
   - если точка использования сломается после переименования, но PRD помечает
     ее как вне scope без явного решения пользователя или отдельного тикета,
     зафиксируй это в `Расхождения с PRD`.
5. Если PRD включает удаление элемента метаданных:
   - выполни диагностику по `1c-metadata-removal-impact`;
   - проверь прямые обращения, metadata-bindings, формы, СКД, роли, запросы,
     движения, обмены, тесты и project-specific source paths в доступном scope;
   - для удаляемого элемента и каждой найденной точки укажи статус `UNUSED`,
     `DEAD_FUNC`, `USED` или `UNCLEAR`;
   - для `DEAD_FUNC` обязательно объясни, почему функционал считается
     неиспользуемым;
   - для `USED` и `UNCLEAR` укажи, какое пользовательское решение требуется
     после обсуждения с аналитиком/бизнесом до plan.
6. Создай или обнови `aidd/docs/research/<ticket>.md`.
7. Перед сохранением явно раздели:
   - факты из кода;
   - reference pattern: локальные паттерны реализации и ссылки на конкретные
     методы/объекты;
   - выводы;
   - требования и их источники;
   - рекомендации по реализации.
8. Если найдено расхождение между PRD и кодом, зафиксируй его явно, а не
   маскируй рекомендацией.
9. Если использовался `1c-rsv`, добавь в research краткий блок MCP:
   projectName, использованные discovery helpers, подтверждающие source-файлы
   и ограничения проверки.

## Структура research

- Scope исследования
- Факты из кода
- Точки встраивания
- Reference pattern: локальные паттерны реализации
- Требования и источники
- Связанные объекты
- Диагностика удаления, если задача удаляет элементы метаданных
- Расхождения с PRD
- Риски регресса
- Рекомендации по реализации
- План проверки в EDT
- MCP 1c-rsv, если использовался
