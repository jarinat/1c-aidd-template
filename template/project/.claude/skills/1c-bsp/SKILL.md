# 1c-bsp

Этот skill описывает переносимый workflow работы со стандартными подсистемами
БСП. Он не хранит project-specific имена модулей, отчетов, подсистем, ролей или
префиксов: такие точки всегда находи в конкретном проекте через reference
patterns.

Skill задает БСП-контракты и workflow, но не навязывает конкретный инструмент.
Для discovery, правок и проверки используй самый узкий доступный структурный
способ: EDT/MCP, Designer, project-local helpers, read-only diff или точечное
чтение файлов по правилам проекта. Если доступен EDT-слой (`edt-mcp`, иначе `1c-rsv`), он обычно
предпочтителен для metadata, СКД, форм, ролей и BSL. Для запросов 1С
дополнительно используй `.claude/skills/1c-query/SKILL.md`.

## Общий workflow

1. Определи, какая подсистема БСП затронута:
   - варианты отчетов / предопределенные варианты / форма отчета;
   - работа с файлами;
   - безопасное хранилище;
   - подключаемые команды;
   - другие стандартные подсистемы или переопределяемые модули.
2. Найди фактическую проектную точку расширения:
   - переопределяемый модуль БСП или project-wrapper над ним;
   - существующий объект, уже подключенный к той же подсистеме;
   - регистрацию в общем модуле, модуле менеджера, форме, обработчике
     обновления или настройках metadata.
3. Не хардкодь имена из другого проекта. Имена вроде
   `ВариантыОтчетов<ИмяСистемы>` допустимы только как найденный факт текущего
   проекта, а не как переносимое правило.
4. Отделяй БСП-инвариант от project-specific решения:
   - инвариант: какой БСП-контракт должен быть выполнен;
   - project-specific: где именно в этом проекте лежит wrapper, какие префиксы,
     роли, подсистемы, варианты и настройки используются.
5. Если БСП хранит вспомогательные данные в ИБ, планируй runtime-проверку или
   ручной шаг обновления этих данных. Статическая проверка исходников не
   доказывает, что данные БСП в информационной базе обновились.
6. Если основной структурированный инструмент не покрывает нужное свойство
   metadata или сценарий записи, зафиксируй инструментальное ограничение и
   применяй fallback только по `.claude/rules/core/tool-usage.md`.

## Reference routing

- При работе с подсистемой БСП `ВариантыОтчетов`, предопределенными вариантами
  отчетов, общей формой отчета, хранилищем вариантов, настройкой доступных
  значений отборов или заголовком варианта прочитай
  `references/report-variants.md`.
- Для `РаботаСФайлами`, безопасного хранилища и других подсистем пока нет
  подтвержденного переносимого reference-файла. Выполни discovery по текущему
  проекту и БСП-документации, а после подтвержденного кейса добавь узкий
  reference в `references/` вместо расширения этого файла.

## Review checklist

- Проверь, что изменение использует переопределяемые точки БСП, а не прямую
  правку библиотечного механизма без причины.
- Проверь, что новый объект зарегистрирован во всех обязательных БСП-точках:
  metadata-свойства, project-wrapper, модуль менеджера/объекта, форма, роли,
  вспомогательные данные ИБ.
- Проверь, что reference pattern использован как инженерный подход, а не как
  источник новых требований.
- Проверь, что сохраненные пользовательские данные, ключи вариантов, файлы,
  хранилища или миграции не затронуты молча.
- В review/feedback указывай конкретный БСП-контракт, который нарушен, и
  проектную точку, где его нужно выполнить.
