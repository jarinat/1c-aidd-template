# 1c-debug-info-tools

Этот skill описывает правила использования MCP-сервера `1c-debug-info`.
Сервер работает поверх опубликованного HTTP-сервиса живой 1С базы и показывает
runtime-состояние: конфигурацию, журнал регистрации, структуру метаданных и
результаты диагностических запросов.

`1c-debug-info` не заменяет выбранный EDT MCP. Для исходников EDT,
редактирования, валидации маркеров, BSL-модулей, форм, СКД, ролей и
метаданных используй соответствующий ему skill. `1c-debug-info` нужен как второй
источник evidence о том, что происходит в запущенной ИБ.

## Когда использовать

- Анализ runtime-ошибок 1С после HTTP-smoke, YAxUnit, ручного сценария или
  другого проверочного runner-а.
- Чтение журнала регистрации за узкое окно времени вокруг падения.
- Проверка версии конфигурации, платформы и режима работы базы перед
  диагностикой.
- Проверка структуры объекта именно в живой базе, если ошибка указывает на
  отсутствующее поле, табличную часть, регистр или перечисление.
- Проверка синтаксиса диагностического запроса через `validate_query`.
- Справка по BSL-функциям и методам через `bsl_syntax_help`.

## Когда не использовать

- Для редактирования исходников, метаданных или настроек EDT.
- Для массового чтения бизнес-данных или выгрузки больших таблиц.
- Как единственный источник истины по коду: runtime evidence нужно связывать
  с исходником через выбранный EDT MCP, `Read` или другой разрешенный discovery.
- Для установки расширения/HTTP-сервиса в базу. Любой install/setup для
  `mcp-1c` является изменением окружения и требует явного решения пользователя.

## Доступные read-only инструменты

- `get_configuration_info` - сведения о конфигурации, версии, платформе и
  режиме работы.
- `get_event_log` - журнал регистрации с фильтрами по периоду, уровню,
  пользователю и лимиту.
- `get_metadata_tree` - дерево метаданных живой базы.
- `get_object_structure` - реквизиты, табличные части, измерения, ресурсы,
  значения перечислений и типы полей.
- `get_form_structure` - структура управляемой формы, если форма доступна
  через HTTP-сервис.
- `validate_query` - синтаксическая проверка запроса 1С без выполнения.
- `bsl_syntax_help` - справка по встроенным функциям и методам BSL.

`execute_query` намеренно не входит в базовый portable allowlist шаблона.
Если проекту нужен такой инструмент, включай его локально в
`.claude/settings.local.json` и используй только для узких диагностических
`ВЫБРАТЬ`-запросов с `limit`.

## Базовый workflow диагностики

1. Выполни `get_configuration_info` и зафиксируй, с какой базой и версией
   работаешь.
2. Если есть падение runner-а, определи узкое окно времени: обычно несколько
   минут вокруг запуска проверки.
3. Вызови `get_event_log` с `level=Ошибка` и разумным `limit`.
4. Найди стабильный симптом: текст исключения, модуль/строку, пользователя,
   HTTP-сценарий, объект метаданных или запрос.
5. Если ошибка указывает на объект метаданных, вызови `get_object_structure`
   для фактической структуры в базе.
6. Если нужна проверка запроса, сначала вызови `validate_query`. Выполнение
   запроса допустимо только если проект локально разрешил `execute_query`.
7. Свяжи runtime evidence с исходниками через выбранный EDT MCP или точечное чтение
   файла. Не делай вывод только по журналу, если можно проверить код.

## Правила безопасности

- Всегда ограничивай период и `limit` для журнала регистрации.
- Не запрашивай и не выводи секреты, токены, персональные данные и большие
  выборки бизнес-данных.
- Не запускай install/setup, публикацию HTTP-сервиса или изменение базы без
  явного подтверждения пользователя.
- Если MCP недоступен, URL неверен или сервис не опубликован, зафиксируй
  tooling blocker и переходи к другому разрешенному evidence.
- Если runtime-база отличается от EDT-исходников, помечай это как отдельный
  риск: база может содержать локальное расширение, несинхронизированные
  изменения или другую публикацию.

## Формат фиксации в debug/research/review

Когда `1c-debug-info` повлиял на вывод, фиксируй коротко:

```text
MCP 1c-debug-info:
- base/config: <configuration/version/platform or unavailable>
- diagnostics: <get_event_log/get_object_structure/validate_query/...>
- evidence: <time window, error text, object/query summary>
- limitations: <MCP unavailable, execute_query not allowed, live DB differs from EDT, ...>
```
