## Контекст

Мета-задача: командная AI-обвязка для 1С/EDT-проектов, универсальная для
Claude Code и Codex, расширяемая проектным и персональным слоями, без
навязывания личного AIDD-воркфлоу. Распространение — через
`EDT-project-template`.

Фактическое состояние на 2026-08-08:

  `feature/team-ai-tools`, коммит `7fef644` (2026-07-31), namespace `mpl-*`,
  9 skills, `doc/standards/`, рукописные Claude-адаптеры. Не запушена, не

Решения пользователя, зафиксированные до этого дизайна:

- Namespace `mplsys-*` — фиксирован.
- Три слоя (корпоративный / проектный / персональный), без AIDD в
  корпоративном слое — фиксированы.
- Состав skills и механика адаптеров — открытые вопросы, решаются ревизией.
- Итерация B берётся за основу «с крайней осторожностью» — через полную
  ревизию (вариант 1: глубокая ручная ревизия в диалоге).
- Слой НЕ попадает в `main` шаблона: живёт в фиче-ветке
  `EDT-project-template`; пилотный проект (MBS) получает его через
  `git pull EDT-project-template <feature-branch>`.
- Самоулучшение: проектная копилка правил с курированием только
  пользователем; механизм не проектируется сейчас — в отчёте ревизии только
  раздел-вход для будущего дизайна.

Подтверждённые внешние факты (важны для критериев):

- Claude Code НЕ читает `AGENTS.md` нативно; официальная рекомендация —
  `CLAUDE.md` с импортом `@AGENTS.md` (симлинк на Windows требует Developer
  Mode). Источник: официальная документация Claude Code (memory).
- Формат SKILL.md — открытый стандарт Agent Skills (agentskills.io);
  Claude ищет skills в `.claude/skills/`, Codex — в `.agents/skills/`;
  формат идентичен. Симлинки skills поддержаны Claude, но для команды на
  Windows ненадёжны, поэтому рендер/копия + валидатор — легитимная
  архитектура.
- Superpowers (obra) — Claude-only плагин с навязанным workflow; для
  корпоративного слоя не подходит, используется только как источник
  паттернов (атомарные skills, Iron Law/red flags, writing-skills).

## Критерии ревизии

Каждый файл/аспект проверяется против пяти источников:

1. Требования Hermes-промпта, включая «Критерии завершения». Отдельно:
   найти итоговый отчёт Hermes и матрицу испытаний; заявленное без
   артефактов-доказательств (испытания обоих CLI, чистый checkout,
   композиция с личным слоем) считается НЕ проверенным.
2. Официальные документации Claude Code и Codex: механика discovery
   (мост для Claude обязателен), каталоги skills, frontmatter по
   стандарту agentskills.io, корректность рендера `.claude` из `.agents`.
3. Инженерное качество 1С-содержания: сверка standards и skills с донором
   (`1c-aidd-template`): не потеряна ли суть при очистке от AIDD, нет ли
   выдуманных API (YAxUnit, Мокито, EDT MCP schemas).
4. Чистота слоёв: нет AIDD-терминологии, личных путей, специфики Avtolid,
   секретов; project/personal расширяемость реально описана и работает;
   namespace `mplsys-` защищён.
5. Пригодность к переносу: коммиты атомарны и переносимы cherry-pick в
   фиче-ветку `EDT-project-template`; посторонние изменения не захвачены.

## Формат результата

Отчёт-матрица в `docs/reviews/2026-08-08-hermes-agent-layer-review.md`
(этот репозиторий):

```text
артефакт -> находки -> вердикт (принять/доработать/выбросить) -> чьё решение
```

- Спорные пункты выносятся пользователю батчами, не по одному.
- Раздел «Не подтверждено испытаниями» — явный список заявленных, но не
  доказанных свойств.
- Раздел «Вход для дизайна самоулучшения» — чего в слое не хватает для
  проектной копилки правил.
- Итог: список доработок для подпроекта 2 (перенос в шаблон).
