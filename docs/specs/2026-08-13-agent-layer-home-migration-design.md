# Дизайн: переезд дома разработки agent layer в шаблон и wiki

> **Переехало.** Актуальная версия — в wiki шаблона, раздел

Дата: 2026-08-13. Статус: принят владельцем.

## Проблема

Знание о корпоративном agent layer `mpl-*` размазано по семи источникам, и
четыре из них живут вне git или вне досягаемости команды.

| # | Источник | Где сейчас | Состояние |
|---|----------|------------|-----------|
| 1 | Слой: `AGENTS.md`, `.agents/**`, `.claude/{CLAUDE.md,rules/mpl,skills/mpl-*,agents/mpl-*}`, `doc/ai/**`, `tools/ai/**` | `EDT-project-template`, ветка слоя | в git, но 8 коммитов не запушены |
| 2 | Доставленные копии слоя | MBS, `hermy-PROSYS-Avtolid` | в git |
| 3 | Спеки, планы, отчёт ревизии, roadmap разработки слоя (12 файлов) | `1c-aidd-template/docs/` | личный GitHub, 43 коммита не запушены, две спеки вообще untracked |
| 4 | Личный AIDD-слой (skills, агенты, правила, скрипты, hook) | `1c-aidd-template/template/project/**`, развёрнут в MBS | источник в личном репо; в проекте gitignored |
| 5 | Журнал мета-проекта: решения владельца, закрытые инкременты, ловушки среды, уроки | auto-память Claude Code для пути MBS | **вне git вообще**, привязан к пути проекта |
| 6 | AIDD-артефакты тикетов MPLSYS | MBS `aidd/docs/**` | untracked |
| 7 | Разрешения и hooks | MBS `.claude/settings*.json` | gitignored |

Из этого следуют три конкретных дефекта.

**Дом разработки — чужой проект.** Слой разрабатывается из рабочего каталога
MBS, потому что там развёрнут личный инструментарий. Контекст мета-проекта
привязан к пути конкретного проекта, а не к самому слою.

**Продуктовой доки нет.** Описание слоя лежит в `doc/ai/README.md` **внутри**
слоя, то есть доступно только тому, кто слой уже получил. Разработчик, который
про слой ещё не знает, узнать о нём неоткуда.

**Самое ценное знание — самое хрупкое.** Журнал мета-проекта (решения
владельца, разобранные ловушки, отвергнутые варианты и причины отказа)
существует в единственном экземпляре в локальном каталоге auto-памяти и
исчезнет вместе с ним.

## Решения владельца

Приняты в обсуждении 2026-08-13.

1. **Дом мета-знания — wiki репозитория `EDT-project-template`**
   (`EDT-project-template.wiki.git`). Причина отказа от каталога `docs/` в самом
   шаблоне: содержимое шаблона доставляется merge'ем в проекты, а история
   разработки слоя проектам не нужна.
2. **В wiki переезжают все четыре класса**: продуктовая дока слоя, журнал
   мета-проекта, спеки и планы разработки, бэклог и roadmap.
3. **Рабочий каталог сессии — `EDT-project-template` с развёрнутым личным
   слоем.** Личный инструментарий синхронизируется туда тем же
   `sync-to-project.ps1`, что и в MBS.
4. **`aidd/**` в MBS не трогаем.** Вне scope этой задачи.

## Целевая топология

| Что | Дом | Роль |
|-----|-----|------|
| Слой (продукт) | `EDT-project-template`, ветка слоя | источник истины кода слоя |
| Дока слоя для команды | wiki, раздел `agent-layer/` | точка входа для того, кто слой ещё не поставил |
| Журнал, спеки, планы, roadmap | wiki, раздел `agent-layer/dev/` | память сопровождающего |
| Личный AIDD-слой | `1c-aidd-template` (личный GitHub) | надстройка, разворачивается в шаблон и MBS |

MBS перестаёт быть местом разработки слоя и остаётся площадкой потребления и
пилотов.

## Структура раздела wiki

Wiki уже используется командой: разделы `EDT/`, `GitLab/`, `YaxUnit/`, `acc/`,
`sonar/`, навигация из корневого `home.md`, страницы с frontmatter `title:`.
Новый раздел следует этой же форме.

```
agent-layer/
  home.md              что это, зачем, три слоя, ссылка на репозиторий и ветку
  Установка.md         поставить в свой проект / обновить существующий
  Каталог-skills.md    таблица skills и ролей с назначением каждого
  EDT-MCP.md           discovery-first, три сервера, как выбрать свой
  Обратная-связь.md    куда сообщать о проблеме и что прикладывать
  dev/
    home.md            навигация «для сопровождающего слоя»
    Журнал.md          бывшая auto-память
    Roadmap.md         бэклог и статус пунктов
    specs/*.md         спеки дизайн-пунктов
    plans/*.md         планы реализации
    reviews/*.md       отчёты ревизий
```

Из корневого `home.md` wiki добавляется ссылка **только** на
`agent-layer/home`. Раздел `dev/` в общую навигацию не выносится: на него
ссылается одна строка внутри `agent-layer/home`, помеченная как материал
сопровождающего. Причина: у продуктовой доки и рабочего лога разная аудитория,
и смешение делает бесполезными обе.

## Механизм контекста

Auto-память Claude Code — единственное, что загружается в сессию само, и она
привязана к пути рабочего каталога. Wiki не загружается никогда. Поэтому память
не отменяется, а сокращается до указателя.

- **Память проекта `EDT-project-template`** (заводится при первой сессии
  оттуда): запись-указатель — где лежит клон wiki, какая страница является
  журналом, требование прочитать её в начале задачи по слою.
- **Память MBS**: записи `team-agent-layer-pilot` и `team-ai-layer-project`
  заменяются одной записью «работа по слою переехала». Без этого старые сессии
  продолжат работать по копии, которая протухает с первого дня.
- **Клон wiki** — постоянный, соседом с шаблоном:
  `C:/Users/jarin/git/sollers/EDT-project-template.wiki`. Читается штатными
  `Read` и `Grep`; отдельного инструмента не требуется.

Клон намеренно не кладётся внутрь чекаута шаблона: это потребовало бы строки в
отслеживаемом `.gitignore` шаблона, то есть правки корпоративного файла ради
личного удобства.

## Правила сопровождения

- Изменение слоя = коммит в шаблоне, **затем** запись в `Журнал.md` со ссылкой
  на SHA. Обратный порядок даёт ссылку в пустоту. Атомарности между
  репозиториями нет — это принятая цена wiki.
- Спека или план нового дизайн-пункта пишется сразу в клон wiki, а не в
  `1c-aidd-template/docs/`.
- Если изменение меняет поверхность слоя (новый skill, новая роль, порядок
  установки), в том же заходе правится соответствующая страница `agent-layer/*`.
- Wiki не покрывается валидатором и CI. Битые ссылки между страницами не
  поймает никто; это известное ограничение, а не упущение.
- Запрет на AIDD-терминологию и проектные ключи действует только для
  корпоративного слоя и держится валидатором. На wiki он не распространяется:
  журнал обязан называть тикеты и проекты, иначе перестаёт быть журналом.

Б0 обязан быть первым: переезд поверх незакоммиченного и незапушенного
состояния теряет работу молча.

Б5 — самый объёмный блок; при необходимости режется постранично, каждая
страница проверяется по фактическому состоянию слоя, а не по памяти.

## Вне scope

- `aidd/docs/**` в MBS (42 файла) — по решению владельца не трогаем.
- Перенос личного AIDD-слоя в корпоративный: решение 2026-08-10 «AIDD остаётся
  личным» в силе.
- MR ветки слоя в `main` шаблона: отдельное решение владельца, от переезда не
  зависит.
- Разрешения `tools/ai/*.cmd` в `settings.json` и устаревшие имена skills в
  `settings.local.json` MBS — известные пробелы, отдельные задачи.

## Риски и принятые цены

| Риск | Цена или смягчение |
|------|--------------------|
| Спека и коммит слоя не могут быть одним изменением | принято; журнал ссылается на SHA, порядок «коммит, затем запись» |
| Wiki не проверяется CI, битые ссылки не ловятся | принято; раздел плоский и мелкий, ссылок немного |
| Журнал в командном пространстве может выглядеть шумом | вынесен в `dev/`, из общей навигации не виден |
| Auto-память остаётся точкой отказа для загрузки контекста | сокращена до указателя: потеря указателя стоит одной строки, а не 675 |
| Личный слой в чекауте шаблона может попасть в коммит | `.gitignore` шаблона **уже** содержит нужный выборочный блок; проверяется в Б1 |
