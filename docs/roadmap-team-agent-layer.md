# Roadmap: командный agent layer MPL Systems (mpl-*)

Обновлено: 2026-08-08. Это верхнеуровневый статус-документ мета-задачи;
обновляй его при каждом существенном шаге. Детальные артефакты — рядом:
спека `specs/2026-08-08-hermes-agent-layer-review-design.md`, план
`plans/2026-08-08-hermes-agent-layer-review.md`, отчёт ревизии
`reviews/2026-08-08-hermes-agent-layer-review.md`, постановка эксперимента
`../prompts/hermes-edt-corporate-agent-layer.md`.

## Цель

Универсальная командная AI-обвязка для 1С/EDT-проектов: работает с Claude
Code и Codex, расширяется проектным и персональным слоями, не навязывает
личный workflow (AIDD остаётся личным слоем). Доставка — через
`EDT-project-template`. Позже, после стабилизации, — общий командный workflow
поверх слоя.

## Архитектура (принято)

- Namespace `mpl-*`; три слоя: корпоративный → проектный (`doc/ai/project`) →
  персональный (gitignored: `AGENTS.local`/`.agents/local/`, `CLAUDE.local.md`,
  личный `.claude/`).
- Один source of truth: канонические skills `.agents/skills/mpl-*` (Codex,
  стандарт Agent Skills), тонкие Claude-адаптеры `.claude/skills/mpl-*`
  генерируются `tools/ai/mpl-render-claude-layer.sh`; мост
  `.claude/CLAUDE.md` = `@../AGENTS.md` (Claude не читает AGENTS.md нативно).
- Инварианты держит код, не проза: `tools/ai/mpl-validate-agent-layer.py`,
  self-tests, CI-job «Проверка agent layer».

### Б1. Находки пилота MPLSYS-4793 — ЗАКРЫТ (`b04e218`, 2026-08-08)

- [x] Предусловие «проект открыт в запущенном EDT» (симптом «проект не
      найден»/пустой список) и порядок действий. **Размещено не в README, а в
      `doc/ai/standards/agent-tools.md`** — предусловие общее для всех трёх
      EDT MCP (все они плагины EDT), а не свойство `1c-rsv`; наблюдённый
      симптом со ссылкой на стандарт — в `mpl-1c-rsv/SKILL.md`.
- [x] Композиция с личным слоем: правило в
      `doc/ai/standards/layers.md` (личный слой — это ещё и исполняемые
      механизмы; блокировка не отменяет корпоративное правило и не разрешает
      обход) + практический раздел в `doc/ai/README.md`.
- [x] Кодировка вывода validator. Диагноз точнее исходного: дело не в
      консоли, а в перенаправленном выводе — Python берёт локаль (cp1251/
      cp866), кириллица приезжает mojibake, а символ вне кодовой страницы даёт
      `UnicodeEncodeError` вместо отчёта. Validator сам переключает stdout/
      stderr в UTF-8, уважая явный `PYTHONIOENCODING`; `ci-check.sh` больше не
      выставляет обходной путь, отдельный self-test снимает переменную и
      проверяет свойство.
- [x] `tools/ai/mpl-commit.cmd` — тонкий launcher (ищет bash, передаёт
      аргументы, сохраняет код возврата). Политика коммита осталась в одном
      файле; батник закреплён в CRLF отдельным правилом `.gitattributes`
      (cmd.exe на LF-варианте способен не найти метку `goto`). Файл добавлен в
      `required_inventory` валидатора.

Найдено и исправлено попутно:

- [x] Прогон self-tests тонул в предупреждениях git о переводах строк (1497
      строк вывода против 109): fixture не несёт `.gitattributes`, поэтому
      подпадала под глобальный `core.autocrlf=true`. Fixture теперь фиксирует
      `core.autocrlf=false`.
- [x] Регрессия `--help` у `mpl-commit.sh`: справка печатается срезом
      `sed -n '2,NNp'`, и расширение шапки обрезало последние строки. Поймана
      существующим self-test'ом.

### Б2. Path-scoped правила — ЗАКРЫТ (`03a3c53`, 2026-08-08)

Реализован этап 1. Спека: `specs/2026-08-08-project-path-rules-design.md`,
план: `plans/2026-08-08-project-path-rules.md`.

- [x] `doc/ai/project/paths/` с `README.md` (таблица-роутер) и
      `sources.example.md` (эталон формата); указатель в
      `project-rules.template.md`.
- [x] Формат правила — frontmatter с единственным ключом `paths` (блочный
      список глобов), буквально в нативном синтаксисе Claude Code.
- [x] Якорь — один пункт в `### Всегда действующие инварианты` корневого
      `AGENTS.md`: сверься с таблицей путей перед тем, как **планировать или
      менять** файл.
- [x] Инварианты в валидаторе: обязательный инвентарь, разбор frontmatter,
      сверка таблицы и файлов в обе стороны со сравнением глобов как множеств,
      защита якоря в `AGENTS.md`. Десять новых self-tests (90 → 100).

Уточнение постановки против исходной формулировки бэклога:

- Целью выбрана **маршрутизация**, а не экономия контекста. Ленивая загрузка
  экономит ценой пропусков: решения «нужен ли тест», «это интеграционный
  контракт», «можно ли править каталог» принимаются до и часто без открытия
  файла из этой зоны.
- Таблица положена в `paths/README.md`, а не в `project-rules.md`: последний
  держит четыре корзины, структуру которых валидатор уже проверяет.
- **Асимметрия механизмов сильнее, чем предполагал бэклог.** У Claude `paths:`
  во frontmatter нативен и ленив (подкаталоги обнаруживаются сами). А Codex
  скоупит вложенные `AGENTS.md` по **рабочему каталогу**, а не по трогаемому
  файлу; в 1С-репозитории агент почти всегда работает из корня, поэтому для
  path-scoping вложенный `AGENTS.md` практически инертен.

Этап 2 (рендер в `.claude/rules/project/*.md` + разыгнорирование `.claude/`) в
силу этой асимметрии может дать нативность **только Claude**, а Codex всё равно
останется на якоре. Запускать его стоит лишь если наблюдения покажут, что
роутер игнорируется; формат правила выбран так, что этап 2 будет копированием,
а не переписыванием.

Попутно закрыт латентный дефект: корпоративные block-list сканы обходили
`doc/ai/project/` и уронили бы валидатор на первых же заполненных проектных
правилах (имя проекта, `PRD`, `tasklist` там законны).

### Б7. Консолидация личного слоя — В РАБОТЕ (И0 закрыт 2026-08-10)

Решение владельца 2026-08-10: личный AIDD-слой (`1c-aidd-template`) больше не

Спека: `specs/2026-08-10-personal-layer-consolidation-design.md`, план И0:
`plans/2026-08-10-personal-layer-i0-superstructure.md`.

Инкременты: ~~И0 переориентация шаблона~~ → ~~И1 EDT MCP и v8std~~ → **И2
технические 1С-skills** → И3 `review-mr` → И4 = бывший Б3, роль исполнителя →

## Как продолжать работу по теме

- Сессия в MBS: контекст подтянется из памяти проекта (Claude Code auto
  memory, запись `team-agent-layer-pilot`) — просто скажи «продолжаем
  командный agent layer, см. roadmap» и укажи этот файл.
- Сессия в шаблоне/мета-репо: начинай с этого файла.
- Правки слоя — только на `feature/team-ai-tools-v2` шаблона, с прогоном
  validator + render --check + self-tests до коммита; в проекты — merge
  ветки шаблона.
- Процесс работы над пунктами бэклога (Claude Code, машина владельца): через
  плагин Superpowers — brainstorming для дизайн-пунктов (Б2, Б4, Б5),
  writing-plans + executing-plans для реализации; спеки и планы — в
  `docs/specs/` и `docs/plans/` этого репозитория. Superpowers — личный
  инструмент оркестратора, в корпоративный слой не переносится; Codex
  работает по слою `mpl-*` без него.
